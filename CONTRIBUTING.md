# Contributing to APAS

Спасибо за интерес к проекту! Это экспериментальная песочница
(`v0.1.0-canary`), поэтому правила простые, но обязательные.

## Что можно и нельзя

**Можно:**
- Предлагать исправления критичных уязвимостей (см. [SECURITY.md](SECURITY.md)).
- Документировать баги и ограничения — даже просто комментарий под Issue.
- Улучшать документацию, README, CI, шаблоны.
- Описывать идеи новых функций и дизайна.

**Пока не стоит:**
- Массово «чинить» известные проблемы v0.1 без обсуждения — многие из них
  задокументированы в [KNOWN-ISSUES.md](docs/KNOWN-ISSUES.md) и могут быть
  задуманы как учебный материал.
- Добавлять секреты, токены, персональные данные. Такие PR будут отклонены.

## Как внести вклад

1. Форкните репозиторий и создайте ветку:
   `git checkout -b feature/<краткое-описание>`
2. Вносите изменения. Придерживайтесь существующего стиля кода (Python 3,
   docstrings, без лишних комментариев).
3. **Проверьте перед PR:**
   ```bash
   python -m compileall -q .        # синтаксис
   make check                       # если доступен make
   ```
   и убедитесь, что CI проходит (secret scan, pip-audit, syntax).
4. Откройте PR на ветку `main`. В описании укажите:
   - что делает изменение;
   - ссылку на Issue, если есть;
   - как проверить.

## Сообщение о проблеме

- Для багов и идей используйте [шаблон Issue](https://github.com/pavelrakcheev/APAS-Telegram-Bot/issues/new/choose).
- Для уязвимостей — приватный [Security Advisory](https://github.com/pavelrakcheev/APAS-Telegram-Bot/security/advisories/new), **не публичный Issue**.

## Правила коммитов

Необязательно, но желательно: краткое сообщение в инфинитиве
(`docs: ...`, `ci: ...`, `fix: ...`, `feat: ...`). Пример:
`ci: add secret scan workflow`.
