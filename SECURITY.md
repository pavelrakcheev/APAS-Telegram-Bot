# Политика безопасности (Security Policy)

> ⚠️ **Проект находится в статусе `canary` (v0.1.0-canary)** — это первая
> публичная экспериментальная версия. Она содержит **задокументированные
> уязвимости** (см. [docs/KNOWN-ISSUES.md](docs/KNOWN-ISSUES.md)) и **не
> предназначена для production-эксплуатации**.

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| `v0.1.0-canary` | ⚠️ Исследовательская — проблемы фиксируются, но не гарантируется выпуск исправлений |

В настоящий момент поддерживается только текущая canary-версия. Исправления
выпускаются по мере возможностей; критичных исправлений безопасности в
отдельных версиях не планируется до перехода к `0.2`.

## Сообщение об уязвимости

**Не создавайте публичный Issue для уязвимостей, касающихся секретов,
персональных данных или эксплуатируемых live-сервисов.**

Как сообщить:

1. **Напишите приватно** на [Security Advisory](https://github.com/pavelrakcheev/APAS-Telegram-Bot/security/advisories/new)
   (рекомендуется) либо создайте Issue с пометкой `[SECURITY]` в заголовке,
   если проблема не содержит секретов.
2. Укажите:
   - версию/коммит, на котором воспроизводится;
   - тип проблемы (IDOR, RCE, SSRF, XSS, утечка данных и т.д.);
   - шаги воспроизведения (без реальных токенов и чужих данных);
   - предполагаемое влияние и severity.
3. Ожидайте ответ в течение 72 часов (это учебный проект, поддержка может
   быть медленной).

## Правила репортера

- **Никогда** не публикуйте реальные значения токенов, паролей, сертификатов
  (`.env`, `config.json`, `*.pfx`), персональные данные пользователей и
  содержимое `Chats/` и `data/*.json`.
- При воспроизведении используйте тестовые/фиктивные данные.
- Не пытайтесь получить доступ к чужим учётным записям и не эксплуатируйте
  уязвимости на live-сервисах за пределами, необходимыми для подтверждения.

## Область ответственности

Проект публикуется «как есть» (лицензия MIT). Автор не несёт ответственности
за последствия использования любой версии, включая уязвимости,
перечисленные в [docs/KNOWN-ISSUES.md](docs/KNOWN-ISSUES.md).

## Известные уязвимости v0.1 (не исправлены)

| ID | Проблема | Severity |
|---|---|---|
| S1 | Секреты в истории проекта (токены, пароль, PFX) | 🔴 Critical |
| S2 | Mini App: нет проверки initData, открыт `/api/debug`, CORS | 🔴 Critical |
| S3 | IDOR в myreports | 🔴 Critical |
| S4 | `/remote` без проверки прав | 🔴 Critical |
| S5 | Условная RCE в `Commands/generator.py` | 🟠 High |
| S6 | Переписки и PII хранятся открытым текстом | 🟠 High |
| S7 | «Удаление профиля» не удаляет данные | 🟠 High |
| S8 | Перебор публичных профилей | 🟠 High |

Полные описания и рекомендации: [docs/KNOWN-ISSUES.md](docs/KNOWN-ISSUES.md),
[AUDIT-01](docs/AUDIT-01-deepseek.md), [AUDIT-02](docs/AUDIT-02-codex.md).

## Перед публичным запуском

Любому, кто планирует использовать проект в реальной эксплуатации,
рекомендуется:

1. Отозвать и перевыпустить все секреты (см. S1).
2. Закрыть уязвимости S2–S8 (см. [SETUP.md → Безопасность](docs/SETUP.md)).
3. Провести повторный независимый аудит.
